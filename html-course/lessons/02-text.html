Lesson 02

Text: headings, paragraphs, lists

Eight or nine elements cover most of the text on most pages. Learn these properly and you can build something real today.

Course home · ← Lesson 01

Headings

There are six levels, <h1> through <h6>. They are an outline, not a set of font sizes. Screen reader users navigate by jumping heading to heading, and search engines read them as your page's table of contents. 

<h1>Making Sourdough</h1>
<h2>Feeding the starter</h2>
<h3>Day one</h3>
<h3>Day two</h3>
<h2>Mixing the dough</h2>

Two rules worth taking seriously:

  • One <h1> per page, and it should say what the page is about.
  • Don't skip levels. An <h4> directly after an <h2> leaves a hole in the outline. If you only want smaller text, that's a CSS decision, not a reason to pick <h5>.

Paragraphs

<p> is the workhorse. Every block of prose goes in one. Don't try to make two paragraphs by putting <br><br> in the middle of one — you'll lose the ability to style them, and assistive technology loses the structure. 

<p>First thought.</p>
<p>Second thought.</p>

When you do want a line break

<br> is for content where the line ending is part of the content: addresses, poems, song lyrics. 

<p>
  Ada Lovelace<br>
  12 Analytical Way<br>
  London
</p>

Renders as

Ada Lovelace
12 Analytical Way
London

Inline semantics: em, strong, and friends

<em> means emphasis — the word you'd stress if you read the sentence aloud. <strong> means importance or urgency. Browsers render them italic and bold by default, but the meaning is the point. 

<p>I said <em>maybe</em>, not yes.</p>
<p><strong>Do not</strong> water the cactus daily.</p>

Renders as

I said maybe, not yes.

Do not water the cactus daily.

There are also <b> and <i>, which mean "bold this" and "italicise this" with no implied meaning. Reach for <em> and <strong> by default; you'll almost never need the other two.

A few more inline elements that come up:

ElementMeans
<code>A fragment of code or a filename. Rendered in a monospace font.
<small>Side comments and fine print, like a legal disclaimer.
<mark>Highlighted for the reader's benefit, e.g. a search term match.
<del> / <ins>Text removed from / added to the document.
<abbr title="…">An abbreviation; the title gives the expansion on hover.
<time datetime="2026-08-24">A date or time in a form machines can read.
<span>Nothing at all. A hook for styling a run of text when no real element fits.

Lists

Unordered lists are for collections where order doesn't matter. Ordered lists are for sequences and rankings. In both cases every direct child must be an <li>. 

<ul>
  <li>Flour</li>
  <li>Water</li>
  <li>Salt</li>
</ul>

<ol>
  <li>Mix the dough</li>
  <li>Rest for an hour</li>
  <li>Fold and rest again</li>
</ol>

Renders as

  • Flour
  • Water
  • Salt
  1. Mix the dough
  2. Rest for an hour
  3. Fold and rest again

Nest a list by putting it inside an <li>, not between two of them: 

<ul>
  <li>Dry ingredients
    <ul>
      <li>Flour</li>
      <li>Salt</li>
    </ul>
  </li>
  <li>Wet ingredients</li>
</ul>

Useful attributes on <ol>: start="5" to begin numbering elsewhere, reversed to count down, and type="a" for letters.

Description lists

<dl> pairs terms with descriptions — glossaries, metadata, key/value facts. <dt> is the term, <dd> is the description, and one term can have several descriptions. 

<dl>
  <dt>Element</dt>
  <dd>An opening tag, its content, and its closing tag.</dd>

  <dt>Attribute</dt>
  <dd>Extra information attached to an opening tag.</dd>
</dl>

Renders as

Element
An opening tag, its content, and its closing tag.
Attribute
Extra information attached to an opening tag.

Quotes

<blockquote> for a quoted block, <q> for a short inline quote. Both take a cite attribute holding the source URL. Visible attribution goes in a <figcaption> or a <cite> element, because the cite attribute isn't shown to anyone. 

<blockquote cite="https://example.com/talk">
  <p>Any sufficiently complicated program contains an
     ad-hoc, informally-specified interpreter.</p>
</blockquote>
<p>— <cite>Greenspun's Tenth Rule</cite></p>

Preformatted text

Remember that HTML collapses whitespace. <pre> is the exception: it keeps every space and newline exactly as typed, in a monospace font. Code blocks are conventionally <pre><code>…</code></pre> — this very page is full of them.

Character entities

Some characters can't be typed literally, because they mean something to HTML. Write them as entities: an ampersand, a name, a semicolon.

Write thisTo getBecause
&lt;<A bare < starts a tag.
&gt;>Pairs with the above; safest to escape both.
&amp;&A bare & starts an entity.
&quot;"Needed inside a double-quoted attribute value.
&nbsp;a space that never breaksKeeps 10&nbsp;kg on one line.
&copy; &mdash; &hellip;© — …Convenience, though with UTF-8 you can paste these directly.
This is why showing code on a web page is fiddly. To display <p> on screen, the file has to contain &lt;p&gt;. Open this lesson's source file and look at any code block — that's exactly what you'll find.

Horizontal rules

<hr> marks a thematic break — a scene change in a story, a shift of topic. It's a meaning, not a decorative line. For a decorative line, use a CSS border.

Try it

  1. Write a page about something you know well, using one <h1>, at least three <h2>s, and real paragraphs under each.
  2. Add an unordered list and an ordered list. Nest a list inside one of the list items.
  3. Emphasise a word with <em> and another with <strong>. Then swap them and read the sentence aloud both ways.
  4. Get the text <h1> is a heading & nothing else to appear literally on the page.
  5. Now do exercise 01: the recipe card.
