Your first page

What an element actually is, why every page starts with the same five lines, and the difference between the head and the body.

HTML is labelling, not drawing

HTML doesn't describe how a page looks. It describes what each piece of content is: this is a heading, this is a paragraph, this is a list, this is a link. The browser then applies its own default styling to those labels. That's why an unstyled page still looks vaguely sensible — bigger headings, indented lists — without you writing a single line of CSS.

Getting the labels right is the whole skill. It's what makes your page work in a screen reader, in Google's index, in reader mode, and on a screen size you never tested.

The anatomy of an element

You label content by wrapping it in tags. A tag is a name in angle brackets. Most content needs an opening tag and a closing tag, and the closing one has a slash: 

<p>Hello, world.</p>
 ↑        ↑        ↑
 opening  content  closing
 tag               tag

Opening tag plus content plus closing tag is called an element. Elements can hold other elements, which is how a page becomes a tree: 

<p>I am <strong>quite</strong> sure about this.</p>

What the browser shows

I am quite sure about this.

Nesting has one rule you cannot break: elements must close in the reverse order they opened. <p><strong>…</strong></p> is fine. <p><strong>…</p></strong> is not, and browsers will silently rearrange your page trying to make sense of it.

Attributes

Tags can carry extra information as attributes — name/value pairs inside the opening tag. A link needs to know where it goes, an image needs to know which file to load: 

<a href="https://example.com">Visit example</a>
<img src="cat.jpg" alt="A ginger cat asleep on a keyboard">

Always put attribute values in double quotes. It's technically optional in some cases, and it will bite you the first time a value contains a space.

Elements with no content

A few elements have nothing to wrap, so they have no closing tag at all. These are called void elements: <img>, <br>, <hr>, <input>, <meta>, <link>. Writing </img> is an error.

The five lines every page starts with

Here is a complete, valid HTML document. Nothing here is decoration — try removing lines and see what breaks.

hello.html

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>My first page</title>
</head>
<body>
  <h1>My first page</h1>
  <p>I made this with my hands.</p>
</body>
</html>

Line by line:

LineWhat it's for
<!DOCTYPE html> Tells the browser to use modern standards mode. Leave it out and browsers fall back to emulating 1990s bugs. It's not really a tag, and it takes no closing tag.
<html lang="en"> The root element — everything else lives inside it. The lang attribute tells screen readers which language to pronounce and browsers which dictionary to spellcheck with.
<head> Information about the page, not shown in it: title, character encoding, stylesheets, description. Covered properly in lesson 08.
<meta charset="utf-8"> Declares the text encoding. Without it, accented letters, curly quotes and emoji can render as garbage. Make it the first thing in the head.
<meta name="viewport" …> Tells phones to use their real width instead of pretending to be a desktop and zooming out. Without this line your page looks tiny on mobile.
<title> The browser tab label, the bookmark name, and the blue line in search results. Required.
<body> Everything the visitor actually sees.
You will type this a hundred times. Don't memorise it by staring — memorise it by typing it from scratch each time you start a file, for the first week. In VS Code, typing ! then Tab expands the whole skeleton, but earn that shortcut first.

Whitespace is collapsed

HTML treats any run of spaces, tabs and newlines as a single space. These two paragraphs render identically: 

<p>Hello        there</p>

<p>Hello
   there</p>

Both render as

Hello there

This is good news: you can indent your markup however you like to keep it readable, and it won't change the output. It also means you can't create space by hammering the space bar — spacing is CSS's job.

Comments

Anything between <!-- and --> is ignored by the browser. Useful for notes to yourself and for temporarily disabling a chunk of markup. 

<!-- Pricing table goes here once we have prices -->
Comments are not private. They're shipped to the browser and anyone can read them with View Source. Never put anything in a comment that you wouldn't say out loud.

Try it

  1. Create a file called hello.html anywhere on your computer and type the skeleton above into it from memory. Double-click it to open it in your browser.
  2. Change the <title> and refresh. Notice that the tab changes but the page doesn't.
  3. Add a second paragraph. Add a <strong> inside it.
  4. Delete the closing </p> of your first paragraph and refresh. Does it still look right? Now open your browser's developer tools (F12), look at the Elements panel, and see what the browser decided your page structure was.
  5. Delete <meta charset="utf-8">, put the word café and an emoji in a paragraph, and refresh. Then put the meta tag back.
