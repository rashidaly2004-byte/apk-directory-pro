Lesson 05

Page structure and semantics

How to lay out a whole page so that its shape means something — and when a plain div is genuinely the right call.

Course home · ← Lesson 04

Block and inline

Elements come in two default flavours. Block elements start on a new line and take the full width available: <p>, <h1>, <div>, <ul>, <section>. Inline elements sit inside a line of text and are only as wide as their content: <a>, <strong>, <em>, <span>, <img>.

The practical consequence: block elements can contain inline elements, but not the other way round. A <div> inside a <p> is invalid, and the browser will close your paragraph early to fix it.

The landmark elements

Before these existed, every site was <div class="header">, <div class="nav">, <div class="footer">. HTML5 turned those conventions into real elements. Screen readers expose them as landmarks that users can jump between, which is the whole reason to use them.

ElementUse it for
<header> Introductory content — site logo and title at the top of the page, or the byline block at the top of an article. You can have several per page.
<nav> A block of navigation links. Not every group of links: reserve it for real navigation.
<main> The page's unique content. Exactly one per page, and nothing that repeats across pages (no site header, no footer) goes inside it.
<section> A thematic grouping that would appear in an outline. Should have a heading.
<article> A self-contained item that would still make sense republished elsewhere: a blog post, a product card, a comment.
<aside> Tangential content — a pull quote, related links, an ad.
<footer> Closing content for its section: copyright, contact, author info.
<div> No meaning whatsoever. A box for CSS to grab. Perfectly fine when there's no meaning to express — a flex wrapper is a div.

A whole page, put together

index.html

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Field Notes — a blog about soil</title>
</head>
<body>

  <header>
    <a href="/"><img src="logo.svg" alt="Field Notes home" width="120" height="32"></a>
    <nav aria-label="Main">
      <ul>
        <li><a href="/">Home</a></li>
        <li><a href="/archive">Archive</a></li>
        <li><a href="/about" aria-current="page">About</a></li>
      </ul>
    </nav>
  </header>

  <main>
    <h1>Field Notes</h1>

    <article>
      <header>
        <h2><a href="/posts/clay">Working with clay soil</a></h2>
        <p><time datetime="2026-08-12">12 August 2026</time> · 6 min read</p>
      </header>
      <p>Clay holds water, which is both the problem and the point…</p>
      <footer><p>Filed under: soil, drainage</p></footer>
    </article>

    <article>
      <h2><a href="/posts/compost">A compost heap that actually heats up</a></h2>
      <p>Three parts brown to one part green, and patience…</p>
    </article>

    <aside aria-labelledby="popular">
      <h2 id="popular">Most read</h2>
      <ul>
        <li><a href="/posts/mulch">Mulch, ranked</a></li>
      </ul>
    </aside>
  </main>

  <footer>
    <p>&copy; 2026 Field Notes. <a href="mailto:hi@example.com">Say hello</a>.</p>
  </footer>

</body>
</html>

Notice the nesting: <article> has its own <header> and <footer>. Those elements are defined relative to their nearest sectioning ancestor, not the page, so this is exactly right.

section vs article vs div

Run through these three questions in order:

  1. Would this still make sense on its own, pulled out and posted elsewhere? Then it's an <article>.
  2. Is it a distinct part of this page that deserves a heading? Then it's a <section>. If you can't think of a heading for it, it probably isn't one.
  3. Neither? It's a <div>, and that's fine. Wrapping things for layout is not a semantic act.
Don't sprinkle semantic tags for their own sake. A <section> with no heading is worse than a <div>: it adds a meaningless entry to the document outline. Wrong semantics are more confusing than none.

Skip links

Keyboard users tab through everything, top to bottom — including your whole navigation, on every page. A skip link, as the very first element in the body, lets them jump straight to the content: 

<body>
  <a class="skip-link" href="#content">Skip to content</a>
  <header>…</header>
  <main id="content">…</main>

CSS normally hides it until it receives keyboard focus. It costs one line and it's one of the highest-value accessibility features you can add.

Two attributes you'll use everywhere

id uniquely names one element — used by fragment links, by <label for>, and by JavaScript. class tags any number of elements with a shared name, and one element can have several, space-separated. Classes are for CSS; ids should be rare. 

<section id="pricing" class="panel panel--wide">…</section>

Other global attributes worth knowing: title (tooltip — don't rely on it, it's invisible on touch), hidden (removes the element from the page entirely), lang (mark a passage in another language), and data-* (your own custom data, e.g. data-user-id="42").

Try it

  1. Rebuild the page above from scratch, without copying, using your own content.
  2. Open your browser's dev tools and use the accessibility or landmarks panel to check that header, nav, main and footer are all detected.
  3. Take any page you've written and try to justify each wrapper element. Turn the ones you can't justify into <div>s.
  4. Add a skip link and tab through the page from the address bar to feel the difference.
  5. Now do exercise 02: the profile page.
