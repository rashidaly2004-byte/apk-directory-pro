Links and paths

The element the whole web is named after. Also: the file-path rules that trip up absolutely everyone at first.

The anchor element

A link is an <a> element with an href attribute — the hypertext reference, i.e. where it goes. 

<a href="https://developer.mozilla.org">MDN Web Docs</a>

Renders as

MDN Web Docs

The text between the tags is what the user clicks, so make it describe the destination. "Click here" and "read more" are useless to someone whose screen reader is listing every link on the page out of context. 

<!-- Bad -->
<p>To see our prices, <a href="/pricing">click here</a>.</p>

<!-- Good -->
<p>See our <a href="/pricing">pricing and plans</a>.</p>

Four kinds of href

1. Absolute URLs

The full address, starting with a scheme. Use these for other people's sites. Always include https:// — without it, href="example.com" is read as a file called "example.com" in the current folder. 

<a href="https://example.com/about">About Example</a>

2. Relative paths

A path interpreted from the folder the current page lives in. This is how you link your own pages together. Given this layout: 

my-site/
├── index.html
├── about.html
├── assets/
│   └── styles.css
└── blog/
    ├── index.html
    └── first-post.html
FromTo reachWrite
index.htmlabout.htmlhref="about.html"
index.htmlblog/first-post.htmlhref="blog/first-post.html"
blog/first-post.htmlindex.htmlhref="../index.html"
blog/first-post.htmlassets/styles.csshref="../assets/styles.css"
blog/first-post.htmlblog/index.htmlhref="index.html"

../ means "up one folder", and you can stack it: ../../. That's the entire system. This lesson links back to the course home page with href="../index.html", because lessons live one folder down.

3. Root-relative paths

A path starting with / means "from the root of the site", ignoring where the current page is. href="/blog/first-post.html" works identically from every page, which is why real sites prefer it.

Root-relative paths don't work when you open a file directly. With a file:// URL, / means the root of your hard drive, not your project. This is the single most common "why is my image broken?" — it happens because you double-clicked the file. Serve the folder instead: python3 -m http.server, then open http://localhost:8000.

4. Fragments

A # followed by an element's id jumps to that element on the page. Give the target an id, then link to it: 

<h2 id="shipping">Shipping</h2>
...
<a href="#shipping">Jump to shipping</a>

<!-- Or on another page -->
<a href="faq.html#shipping">Shipping FAQ</a>

Ids must be unique on the page and can't contain spaces. Fragment links are how any "table of contents" or "back to top" link works.

Other schemes

<a href="mailto:hi@example.com">Email us</a>
<a href="tel:+441234567890">Call us</a>
<a href="report.pdf" download>Download the report</a>

Opening in a new tab

<a href="https://example.com" target="_blank" rel="noopener noreferrer">
  Example (opens in a new tab)
</a>

target="_blank" opens a new tab; rel="noopener noreferrer" stops the new page from getting a scripting handle back to yours. Modern browsers imply noopener, but it's still worth writing.

Use this sparingly. It takes the back button away from the user, and it should never be a surprise — say so in the link text or with an icon.

Links can wrap anything

An <a> may contain images, headings, whole blocks. That's how a clickable card works: 

<a href="post.html">
  <img src="thumb.jpg" alt="">
  <h3>How I learned HTML</h3>
  <p>A short account of an afternoon well spent.</p>
</a>

The one thing you must not do is nest a link inside a link, or put a <button> inside one.

If it navigates, it's a link. If it acts, it's a button. A <div> with a click handler is neither: it can't be tabbed to, can't be opened in a new tab, and is invisible to screen readers. Never fake a link with a div.

Navigation

A group of links that navigates the site belongs in a <nav>, marked up as a list — because it is a list: 

<nav aria-label="Main">
  <ul>
    <li><a href="/">Home</a></li>
    <li><a href="/work">Work</a></li>
    <li><a href="/about" aria-current="page">About</a></li>
  </ul>
</nav>

aria-current="page" tells assistive technology which item is the page you're on. More on <nav> in lesson 05.

Try it

  1. Make two files, index.html and about.html, in the same folder, and link each to the other. Click back and forth.
  2. Move about.html into a pages/ folder and fix both links.
  3. Add three <h2>s with ids to one page and build a table of contents that jumps to each.
  4. Add a "back to top" link at the bottom of the page.
  5. Take a link that says "click here" and rewrite it so the link text alone tells you where it goes.
