Lesson 07

Forms and inputs

Where HTML stops describing content and starts collecting it. Also where the browser gives you keyboards, date pickers and validation for free — if you use the right types.

Course home · ← Lesson 06

The shape of a form

<form action="/subscribe" method="post">
  <label for="email">Email address</label>
  <input type="email" id="email" name="email" required>
  <button type="submit">Subscribe</button>
</form>
PieceJob
actionThe URL the data is sent to. Omit it to post back to the current page.
method get puts the data in the URL's query string — for searches and filters. post puts it in the request body — for anything that changes state or is remotely private.
name The key the value is sent under. A field with no name is never submitted, which is the classic silent form bug.
idConnects the input to its <label>. Not sent anywhere.
<button type="submit">Sends the form. Also fires when the user presses Enter in a text field.

Labels are not optional

Every input needs a label, and the label's for must match the input's id. This gives you three things: a screen reader announces the field's purpose, clicking the label focuses the field, and checkbox hit areas get usefully bigger. 

<!-- Explicit: for matches id -->
<label for="city">City</label>
<input type="text" id="city" name="city">

<!-- Implicit: the input lives inside the label -->
<label>City <input type="text" name="city"></label>
A placeholder is not a label. It disappears the moment someone types, it's often too low-contrast to read, and some screen readers ignore it. Use placeholder only for a format hint — placeholder="+44 7700 900000" — on top of a real label.

Input types

type changes the keyboard on phones, the on-screen widget, and the validation the browser performs. Picking the right one is the cheapest usability win in HTML.

TypeGives you
textThe default single-line field.
emailAn @-key keyboard and a check that it looks like an address.
passwordMasked characters.
telA phone keypad. No validation — phone formats vary too much.
urlRequires a scheme like https://.
numberA numeric field with min, max, step. Not for phone numbers or card numbers.
date, time, datetime-local, monthNative pickers.
rangeA slider. Always pair it with a visible value.
colorA colour picker.
fileA file chooser. Add accept="image/*" and multiple as needed.
searchA search field, often with a clear button.
checkboxIndependent on/off choices.
radioOne choice from a set. All options share the same name.
hiddenA value submitted without being shown.

Multi-line text, dropdowns and groups

<label for="bio">Short bio</label>
<textarea id="bio" name="bio" rows="4" maxlength="300"></textarea>

<label for="country">Country</label>
<select id="country" name="country">
  <option value="">Choose…</option>
  <optgroup label="Europe">
    <option value="uk">United Kingdom</option>
    <option value="de">Germany</option>
  </optgroup>
  <optgroup label="Asia">
    <option value="in" selected>India</option>
  </optgroup>
</select>

<textarea> is not a void element and its default value goes between the tags, not in a value attribute. Keep the opening and closing tags adjacent, because every space inside them counts as content.

Radios and checkboxes

Radio buttons only behave as a group if they share a name. Each needs its own id and value. Wrap the set in a <fieldset> with a <legend> — the legend is what tells a screen reader user what the group is asking. 

<fieldset>
  <legend>Delivery speed</legend>

  <input type="radio" id="std" name="speed" value="standard" checked>
  <label for="std">Standard (3–5 days)</label>

  <input type="radio" id="exp" name="speed" value="express">
  <label for="exp">Express (next day)</label>
</fieldset>

Validation you get for free

The browser will refuse to submit and show its own message when these constraints fail. No JavaScript involved.

AttributeMeaning
requiredMust not be empty.
minlength / maxlengthCharacter count limits for text fields.
min / max / stepNumeric and date range limits.
pattern="[0-9]{4}"A regular expression the value must match. Pair with title to explain the format.
autocomplete="email"Lets the browser fill it correctly. Use the standard token names — this genuinely helps people.
novalidate (on the form)Turns the whole lot off.
Client-side validation is a convenience, not a security control. Anyone can edit your HTML or post to your endpoint directly. Whatever you check here, check again on the server.

Seating

Click the word "Inside" rather than the radio itself — it still works, because the label is correctly associated. That's your quick test for whether you wired the labels up properly.

Other useful bits

  • disabled — greys out a control and excludes it from submission.
  • readonly — value can't be edited but is still submitted.
  • autofocus — focuses on load. One per page at most, and skip it on mobile.
  • <datalist> — suggestions for a text input while still allowing free text.
  • <output> — where a calculated result goes.
  • <progress> and <meter> — a task's completion, and a value in a known range.

Try it

  1. Build a contact form with name, email, subject dropdown and message. Label everything.
  2. Set method="get", submit it, and read the query string in the address bar. Now remove one field's name and submit again — watch it disappear.
  3. Add required to two fields and submit empty to see the browser's messages.
  4. Open the form on a phone, or in a browser's device emulation, and check that the email field brings up the @ keyboard.
  5. Now do exercise 03: the signup form.
