Lesson 04

Images and media

One tag, four attributes, and one piece of writing that matters more than all of them: the alt text.

Course home · ← Lesson 03

The img element

<img> is a void element — no closing tag, no content. It has two required attributes and two you should always include anyway. 

<img src="../assets/sample-photo.svg"
     alt="Illustration of layered hills against a sunset sky"
     width="320" height="200">

Renders as

AttributeWhat it does
srcWhere the image file is. Same path rules as links (lesson 03).
altText shown if the image fails, and read aloud by screen readers. Required.
width / height The image's real pixel dimensions. Supply both so the browser can reserve space and the page stops jumping around as images load. CSS can still resize it.
loading="lazy"Defer loading until the image is near the viewport. Great for images below the fold, bad for the top one.

Writing alt text

The test: if the image vanished, what sentence would keep the page making sense? Write that.

  • Describe the purpose, not the pixels. For a headshot on an about page, "Photo of Rashid" beats "man in blue shirt in front of window".
  • Don't start with "image of" or "picture of" — screen readers already announce that it's an image.
  • If the image is purely decorative, use an empty alt: alt="". That tells assistive tech to skip it. Omitting the attribute entirely is different and worse — then the screen reader may read out the filename.
  • If the image contains text, put that text in the alt.
  • If the image is inside a link and is the only thing in it, the alt must describe where the link goes, not the picture.
<!-- Meaningful -->
<img src="chart.png" alt="Revenue tripled between 2024 and 2026">

<!-- Decorative flourish -->
<img src="squiggle.svg" alt="">

<!-- Image as the whole link -->
<a href="/"><img src="logo.svg" alt="Acme home"></a>

Which file format

FormatUse for
.svgLogos, icons, diagrams. Vector, so it's sharp at any size and usually tiny.
.webp / .avifPhotos. Much smaller than JPEG at the same quality; both are widely supported now.
.jpgPhotos, when you want the safest possible compatibility.
.pngScreenshots, and anything needing transparency where SVG won't do.
.gifNothing, really. Use a muted, looping <video> instead — far smaller.

Figures and captions

When an image needs a visible caption, wrap it in a <figure> and put the caption in a <figcaption>. This associates the two so assistive tech knows the caption belongs to the image — something a plain paragraph underneath can't do. 

<figure>
  <img src="../assets/sample-photo.svg" alt="Layered hills at sunset" width="320" height="200">
  <figcaption>Fig 1. Sunset over the ridge, drawn entirely in SVG.</figcaption>
</figure>

Renders as

A <figure> isn't only for images — it also suits code samples, diagrams and quotes that are referenced from the text.

Different images for different screens

srcset offers the browser several sizes of the same image and lets it pick based on screen width and pixel density. sizes tells it how wide the image will actually be displayed. 

<img src="photo-800.jpg"
     srcset="photo-400.jpg 400w, photo-800.jpg 800w, photo-1600.jpg 1600w"
     sizes="(max-width: 600px) 100vw, 800px"
     alt="The workshop at dawn" width="800" height="500">

<picture> goes further: you specify the alternatives yourself, and the browser takes the first <source> it can use. It's how you offer a modern format with a fallback, or crop differently on mobile. 

<picture>
  <source srcset="hero.avif" type="image/avif">
  <source srcset="hero.webp" type="image/webp">
  <img src="hero.jpg" alt="The workshop at dawn" width="1200" height="600">
</picture>

The <img> inside is mandatory — it's the fallback, and it's where alt lives.

Video and audio

<video src="demo.mp4" controls width="640" height="360"
       poster="demo-thumb.jpg" preload="metadata">
  <track kind="captions" src="demo.en.vtt" srclang="en" label="English" default>
  <p>Your browser can't play video. <a href="demo.mp4">Download it</a>.</p>
</video>

<audio src="episode.mp3" controls></audio>
AttributeEffect
controlsShow the play/pause UI. Without it there's no way to start playback.
posterStill image shown before play.
preload="none|metadata|auto"How much to fetch up front. metadata is a polite default.
muted autoplay loop playsinlineThe combination needed for a silent background clip. Browsers block autoplay with sound.
<track kind="captions">Subtitles from a .vtt file. This is what makes video accessible.
Never autoplay with sound. Browsers will block it, and users who aren't blocked will leave. If a clip must autoplay, it must be muted.

Embedding other pages

<iframe> puts another document inside yours — maps, YouTube players, payment widgets. Give it a title so screen reader users know what it is, and constrain what it may do: 

<iframe src="https://www.youtube.com/embed/VIDEO_ID"
        title="Product tour video"
        width="560" height="315"
        loading="lazy"
        allowfullscreen></iframe>

Try it

  1. Put a real image next to your HTML file and display it. Then move it into an images/ folder and fix the src.
  2. Deliberately misspell the src and reload. That's what your alt text looks like to someone with a slow connection.
  3. Wrap the image in a <figure> with a caption.
  4. Write alt text for: your logo, a decorative divider, and a screenshot of an error message. Three different answers.
  5. Make an image into a link back to your home page.
