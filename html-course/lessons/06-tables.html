Lesson 06

Tables

For data with rows and columns, a table is the right answer and nothing else comes close. For anything else, it isn't.

Course home · ← Lesson 05

The parts of a table

A table is rows of cells. <tr> is a row, <td> is a data cell, <th> is a header cell. Group rows with <thead>, <tbody> and <tfoot>, and give the table a <caption> as its accessible name. 

<table>
  <caption>Office plants and their watering needs</caption>
  <thead>
    <tr>
      <th scope="col">Plant</th>
      <th scope="col">Light</th>
      <th scope="col">Water</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">Snake plant</th>
      <td>Low to bright</td>
      <td>Every 3 weeks</td>
    </tr>
    <tr>
      <th scope="row">Fern</th>
      <td>Indirect</td>
      <td>Twice a week</td>
    </tr>
  </tbody>
</table>

Renders as

Office plants and their watering needs
Plant Light Water
Snake plant Low to bright Every 3 weeks
Fern Indirect Twice a week
An unstyled table has no visible grid. Browsers draw no borders by default, so the demo above only looks like a table because this page's stylesheet gives it border-collapse, borders and padding. Old tutorials do it with border="1" cellpadding="6" attributes on the <table> — those are deprecated, and a validator will flag them. Use CSS.

scope is the part people skip

A sighted reader sees which column a cell belongs to. A screen reader has to be told. Marking header cells with <th> and adding scope="col" or scope="row" lets it announce "Water: every 3 weeks" as it moves through the row, instead of reading a stream of disconnected values.

Column headers get scope="col". The first cell of a row that names that row gets scope="row". That's the whole rule, and it takes ten seconds.

Spanning cells

colspan makes a cell wider, rowspan makes it taller. The spanned cells are then not written — this is where hand-built tables usually go wrong, since every row still has to add up to the same number of columns. 

<table>
  <tbody>
    <tr>
      <th scope="col">Item</th>
      <th scope="col">Qty</th>
      <th scope="col">Price</th>
    </tr>
    <tr>
      <td>Notebook</td><td>2</td><td>£7.00</td>
    </tr>
    <tr>
      <td colspan="2">Total</td><td>£7.00</td>
    </tr>
  </tbody>
</table>

Renders as

Item Qty Price
Notebook2£7.00
Total£7.00

The total row has two cells, not three, because the first one covers two columns. If you ever see a stray extra column appear in a table, count your spans.

colgroup

<colgroup> lets you target whole columns for styling without adding a class to every single cell: 

<table>
  <colgroup>
    <col>
    <col span="2" class="numeric">
  </colgroup>
  …
</table>

What tables are not for

In the 1990s, tables were the only way to lay out a page, so sites were built as nested grids of invisible cells. That era is over: CSS Grid and Flexbox do layout properly. Using a table for layout produces markup that reads as gibberish in a screen reader and collapses on a phone.

The test is simple. Does the content have a meaningful relationship between rows and columns, such that a cell needs both its row and its column to be understood? Then it's a table. Is it a grid of cards that happens to look tabular? Then it's a list, styled with CSS.

Wide tables on small screens: wrap the table in a <div style="overflow-x: auto"> so it scrolls sideways rather than breaking the layout. Add tabindex="0" to that wrapper so keyboard users can scroll it too.

Try it

  1. Build a table of the next five days: date, forecast, high, low. Use <caption>, <thead> and <tbody>.
  2. Add scope to every header cell.
  3. Add a final row that spans the first two columns and shows an average.
  4. Delete one <td> from the middle of a row and reload — see how the whole column shifts. That's what a mis-counted colspan looks like.
